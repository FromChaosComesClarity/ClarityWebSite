Clarity now runs on a television older than most of my games

Couch Mode is built around cover art. A tube TV has nowhere to put any.

I wanted my library on a CRT, so I plugged the machine into one and started Couch Mode. It was not broken. It was unusable, which is worse, because there is nothing to fix.

Couch Mode is built around artwork, and artwork is the one thing a tube cannot give you. Over a composite cable a cover ends up about the width of your thumb and the colour smears into a haze. Thin lines flicker, because half the picture is drawn on one pass and half on the next, so a one pixel rule is only ever there for half the time. And every set crops the edges by a different amount, so anything near a corner is simply gone on somebody’s television.

So there is a third face now. Not Couch at a smaller size: a menu, where a row of text is the interface and art is only there to tell two similar rows apart. Up and down move, one button goes in, one goes back. That is the whole thing, because that is the vocabulary a D-pad has and the one a TV menu has always had. Arrow keys and Enter work too.

Everything happens there. Install and uninstall your GOG and Epic games, fetch artwork and details, search, filter by store, make playlists, mark favourites, switch a game to the compatibility mode that fixes it, and play. You never get up and walk to the desk, which was the entire point of building it.

It follows your Omarchy theme while it is open, so changing the theme restyles it where it stands.

29 September 2026 · game fix · Clarity 1.18.0

The Witcher did nothing at all when I pressed play

No window, no error, not even a log. The game had quietly decided it was not installed.

This is the most annoying way for a game to fail. A crash leaves you something to read. The Witcher left nothing: press play, and the library sits there as though you had not.

When GOG’s own installer runs on Windows it does not just copy files, it writes down where it put them. On Linux the download finishes and that is the end of it, so the note is never written.

Both GOG’s launcher and the game itself look for that note before they do anything else, and neither has a backup plan. They do not find it, they give up, and they exit reporting success. That last part is why nothing anywhere had a complaint to show you.

Clarity writes the note itself now, when you press play, and rewrites it if you ever move the game. It sets the language at the same time, which sounds like a detail and is not: without it the game starts and every menu is blank.

29 September 2026 · feature · Clarity 1.18.0

Doom mods, with the soundtrack you already own

Brutal Doom on IDKFA, chosen at the moment you press play, built from a game already on your disk.

Launch a Doom mod in Clarity and it already asks which Doom you want it to run on. Now it asks which music, too.

Nothing is downloaded. If you own the DOOM + DOOM II re-release, the alternate soundtracks are already sitting inside it: Andrew Hulshult’s IDKFA, and the original Bobby Prince score re-recorded. Clarity builds the music file from the copy you own, and the audio that comes out is byte for byte the audio that went in. If you do not own the re-release, the question is never asked, because there would be nothing to answer it with.

I expected this to be an afternoon of renaming things. It was not, and the reason is properly stupid: the name of a music track does not tell you which song is in it, and which song it is changes from one game to the next.

Doom reuses its own music, so one song can be asked for under two names. Replace only the name you recognise and half the game drops back to MIDI while the other half plays the new score. Worse, TNT uses the very same names for entirely different music, so going by name alone would confidently put the wrong song on nearly every map of it.

So Clarity does not go by name. It fingerprints the music in your own copies and matches on what the songs actually are. Doom and Doom II come out right, and TNT is correctly offered nothing at all, which is the right answer and a much better one than something plausible and wrong.

16 September 2026 · game fix · Clarity 1.17.0

Arcanum closed the instant I pressed play

No window, no error. The thing meant to fix the game was what broke it.

I installed Arcanum, pressed play, and nothing happened. No window, no error, just the library sitting there as if I had not clicked. I fixed this game years ago on another system, so it felt personal.

GOG includes a small helper file with Arcanum that keeps it running on modern Windows. Clarity normally lets a game use the helper it came with, and that is exactly what rescues Quake and Resident Evil 2. Arcanum turns out to be the opposite case: on Linux that helper cannot work, and it takes the game down with it before anything appears on screen.

Clarity now leaves it out for this one game, and Arcanum starts. Nothing is deleted, nothing to set up, and the helper stays on disk for anyone who wants it back on Windows.

One more thing came out of it. While I was in there I found the per-game fixes had quietly stopped being applied at all, so the whole list on the fixes page was doing nothing. That is fixed too, which means the rest of them are working again.

10 September 2026 · game fix · Clarity 1.15.3

Fallout: London installed perfectly, then refused to start

Music over a black screen, a warning about loose files, and a browser tab nobody asked for.

The GOG one-click edition downloads beautifully. Every file arrives, nothing errors, the library shows it as installed. Then you press play and the game opens for about a second, the music starts over a black screen, a little warning appears about loose files, and your browser opens a mod page you did not ask for.

It is the second time this exact shape of fault has turned up, and it has the same cause as the first. A GOG installer does not stop when the files land. It performs finishing steps afterwards, copying configuration and a plugin list into places the game will look. On Windows those steps run. On Linux the download finishes and that is the end of it, so the game is complete and misconfigured at the same time, which is the most annoying way for something to be broken.

Two things were missing. London’s plugin list never reached the game, so none of London ever loaded, which is the black screen. And loose file loading stayed switched off, which is what the warning was about before the game gave up.

The second one cost the evening. The setting that turns loose files on is written by GOG into one file, and Fallout 4 only honours it from a different one. So it was there, it looked right, and it did nothing. Putting the same lines where the engine actually reads them is what let the game start, and it survives Fallout 4 rewriting its own settings on every launch, which it does.

Both steps now run when you press play, repairing the install you already have. No reinstall, nothing to configure, and it only touches files that are missing, so if you have set any of this up by hand it is left exactly as you left it.
